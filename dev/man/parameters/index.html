Parameters

Parameters are set with setparam! and read with getparam (or getparam! into a preallocated buffer), with the parameter strings of CUDSS.jl. They come in three groups.

  • Configuration parameters (CONFIG_PARAMETERS, cuDSS's cudssConfigParam_t): algorithm choices and tolerances, read by the next phase that uses them.
  • Data parameters (DATA_PARAMETERS and CUDSS08_DATA_PARAMETERS, cuDSS's cudssDataParam_t): inputs provided by the user (user_perm, user_schur_indices, user_host_interrupt, …) and outputs computed by the solver (info, inertia, diag, perm_row, …).
  • Extensions (EXTRA_PARAMETERS): parameters cuDSS does not have, such as pivot_sign, pivot_stats, ir_mode and pivot_pairs.

Every parameter is validated when it is set: an unknown name raises an ArgumentError and a bad value an InvalidValueError. A parameter that exists in cuDSS but is not implemented is handled in one of three ways (see below).

using SparseDirectSolver
opts = Options(ir_n_steps = 2, pivot_threshold = 0.1)
getparam(opts, "ir_n_steps"), getparam(opts, "reordering_alg")
(2, "default")

How unimplemented parameters are handled

handlingparameters
raise NotSupportedErrordevice_count other than 1, device_indices, comm_device, comm_host (when set or read); solve_alg = "algo1" (T24–T26, at the solve), user_nd_partition_tree (T30) and schedule = "syncfree" (at the analysis)
warn once and ignorea non-default hybrid_memory_mode, hybrid_device_memory_limit or hybrid_execute_mode (T27); reordering_alg "algo1"/"algo2", which fall back to the symmetric-pattern ordering with in-front pivoting
accept and ignore silentlymax_lu_nnz, host_nthreads, use_cuda_register_memory; schedule = "subtree+level", which behaves as "auto"

The details of each are in the Options docstring and in setparam!.

Pivot pairs

For the symmetric indefinite structures "S" and "H", pivot_pairs = "default" orders a row whose diagonal is zero or negligible (below pivot_pair_tolerance times the largest entry of its row) and whose pivot would be structurally zero together with a 2×2 pivot partner, so that the in-front Bunch–Kaufman pivoting can form the 2×2 block; "all" pairs every candidate (about 2× nnz(L) on KKT systems) and "none" turns the pairs off. With matching_alg = "algo5"/"algo6" the pairs come from the cycles of the matching instead. The pairs are decided from the values present when "analysis" runs, so run the analysis after the first assembly of the matrix. See Symmetric indefinite systems.

Data parameters

The outputs and when they become available are tabulated in the docstring of getparam. For a uniform batch the per-factorization outputs are vectors with one entry per member.

Differences from cuDSS

  • "info" reports the original column of the first failed pivot.
  • getparam! replaces the set-buffer-then-get protocol of cuDSS for vector outputs.
  • pivot_sign chooses the sign of the perturbation of each row, so that a perturbed KKT system keeps the inertia an interior-point method expects.
  • pivot_stats returns (npos, nneg, nzero, nperturbed, n2x2) in one read.
