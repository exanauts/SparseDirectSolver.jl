CUDA extension

Loaded with using CUDA. It accepts the sparse matrices of cuSPARSE and routes the dense operations of large fronts to cuBLAS and cuSOLVER.

cuSPARSE.CuSparseMatrixCSR — Method
CuSparseMatrixCSR(A::CSR)

The stored CSR matrix of A (the transposed flag is not applied) as a CuSparseMatrixCSR. One-based arrays are shared; zero-based index arrays are copied and rebased. Batches (nbatch(A) > 1) are rejected.

SparseDirectSolver.capture_graph — Method
capture_graph(::CUDABackend, f)

f() captured into a CUDA graph (CUDACore.capture) and instantiated; the returned CuGraphExec replays it on the task's stream when called, so it stays ordered with the caller's other work on that stream. nothing when the capture fails (an operation that cannot be captured, or an error raised while capturing: nothing has run then, and the caller launches f eagerly, where a genuine error raises again).

The capture runs on a fresh non-blocking stream to which the task's cuSOLVER dense and cuBLAS handles are bound before the capture begins (CUDACore.stream!(handle, s)), so that a vendor dense call inside f finds its handle already on the capture stream. Otherwise the first cuSOLVER.dense_handle() in the capture calls cusolverDnSetStream on the stream being captured, which cuSOLVER 12.3.5 (CUDA 13.4) answers by invalidating the capture (#174; CUDA.jl 6 captures on a dedicated stream, not on the task's). Afterwards both handles are bound back to the task's stream.

A captured vendor potrf bakes in the pointer of the task's cuSOLVER workspace (with_workspace grows that buffer by reallocating it when a larger bufferSize comes along). The eager factorization that precedes a capture sizes it for the solver's widest front, so the graph is consistent for that solver; a wider front factored later in the same task by another solver would reallocate the workspace under a still-replayed graph. One solver per task (MadNLP's pattern) keeps this theoretical; a capture of the stock path (T38) should size the workspace for the widest front of every live solver before capturing.

SparseDirectSolver.max_local_bytes — Method
max_local_bytes(::CUDABackend) -> Int

48 KiB: @localmem is static shared memory, and ptxas rejects more than 48 KiB of static shared data per kernel on every CUDA device (larger amounts need dynamic shared memory with an opt-in attribute). The regime-A kernels therefore stop at the 48 KiB class on CUDA (issue #60).
