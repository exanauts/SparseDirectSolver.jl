Parameters

Parameters are set with setparam! and read with getparam (or getparam! into a preallocated buffer), with the parameter strings of CUDSS.jl. They come in three groups.

  • Configuration parameters (CONFIG_PARAMETERS, cuDSS's cudssConfigParam_t): algorithm choices and tolerances, read by the next phase that uses them.
  • Data parameters (DATA_PARAMETERS and CUDSS08_DATA_PARAMETERS, cuDSS's cudssDataParam_t): inputs provided by the user (user_perm, user_schur_indices, user_host_interrupt, …) and outputs computed by the solver (info, inertia, diag, perm_row, …).
  • Extensions (EXTRA_PARAMETERS): parameters cuDSS does not have, such as pivot_sign, pivot_stats, ir_mode and pivot_pairs.

Every parameter is validated when it is set: an unknown name raises an ArgumentError, a bad value an InvalidValueError, and a parameter that exists in cuDSS but is not implemented (the hybrid memory and multi-GPU modes, for example) a NotSupportedError.

using SparseDirectSolver
opts = Options(ir_n_steps = 2, pivot_threshold = 0.1)
getparam(opts, "ir_n_steps"), getparam(opts, "reordering_alg")
(2, "default")

The fields of Options with their defaults are listed in its docstring. The ones that matter most in practice:

Data parameters

The outputs and when they become available are tabulated in the docstring of getparam. For a uniform batch the per-factorization outputs are vectors with one entry per member.

Differences from cuDSS

  • "info" reports the original column of the first failed pivot.
  • getparam! replaces the set-buffer-then-get protocol of cuDSS for vector outputs.
  • pivot_sign chooses the sign of the perturbation of each row, so that a perturbed KKT system keeps the inertia an interior-point method expects.
  • pivot_stats returns (npos, nneg, nzero, nperturbed, n2x2) in one read.
